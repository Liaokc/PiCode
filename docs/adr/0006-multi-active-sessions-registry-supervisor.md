# 多活动会话：supervisor 注册表语义 + 单窗口会话视图注册表

1.1 票 20 推翻 ADR-0003 的 α 交付形态（单活动会话：切换即终止前一个 host），改为**注册表语义**：单窗口内多个会话同时处于运行态，每个会话独占一个 host 子进程（ADR-0003 的 β 形状本来就是按此设计，本 ADR 只改交付形态，不改进程架构）。

## 决策

**host 生命周期：注册表，而非替换。** supervisor 维护 sessionId → host 子进程的注册表；`create_session`/`resume_session` 只新增实例，**永不因切换而终止**任何在跑的 host。会话与 host 的绑定随 host 进程的 `session_created` 公告建立；同 host 内换会话（fork 重公告）触发 `session_detached` 让旧会话从注册表摘除（其文件保留，可再次 resume），同 sessionId 被另一个 host 重新公告（对在本应用内仍持有 host 的会话做全量 resume 接管）时终止旧 host（预期退出，不广播崩溃）。

**单窗口视图挂载：会话视图注册表。** 渲染层新增唯一的纯状态模块——会话注册表（sessionId → 该会话的视图状态 + 焦点路由）；既有 chat reducer 原样复用、按会话各折叠一份。**多 host 并存与视图挂载的关系：host 全时存活并产出事件，视图只决定"哪一个会话的状态被渲染"**——契约事件全部携带会话作用域（`session_event` 包装），无论聚焦与否都持续折叠进各自会话的状态，仅聚焦会话上屏。

**后台渲染策略：不渲染 + 追平。** 后台会话的屏幕不刷新（不做离屏渲染、不做虚拟缓冲），但事件流照常收集、会话文件照常增长；切回时视图重挂载，直接呈现已追平的完整转录并恢复实时流——无重复条目、无缝隙。审批挂起等后台注意点 UX 另立（票 25），不在本 ADR 范围。

**退出语义：全部终止，无孤儿。** 退出时 supervisor 对注册表内全部 host 逐一执行礼貌关闭（shutdown 命令 → SIGTERM → SIGKILL 宽限链），承诺不变；会话文件保留，resume 可续。崩溃隔离从"进程级"细化为"会话级"：任一 host 崩溃仅该会话报错横幅，其余会话不受影响。

## 为什么难回退 / 反直觉 / 真取舍

- **难回退**：会话状态从"渲染层单实例"改为注册表后，回退到 α 等于丢弃多会话视图状态与事件路由契约（`session_event` 作用域包装），涉及契约、supervisor、渲染层三处的逆向迁移。
- **反直觉**：屏幕上只有一个转录区，用户看不到的会话仍在消耗进程与 token——"看不见 = 停止"的直觉在这里不成立（本 ADR 明文化这一点作为设计意图，而非缺陷）。
- **真取舍**：每会话一个常驻 host 进程，内存与句柄随会话数线性增长；本 ADR 接受该成本（不设硬上限，超载用户自负），换取后台任务绝不被切换杀死的核心承诺。

## 被拒方案

- **维持 α + 队列化**（切走时把运行中的会话排队暂停、切回再续）：agent 运行态无法安全序列化暂停/恢复，队列化等于变相杀任务，且与"后台文件持续增长"的实测对照（ZCode 同机制）不符。
- **双窗口**（每个活动会话一个窗口）：窗口管理、侧栏索引、Bridge 投影等全部组件都要多实例化，成本远超注册表方案；且操作者心智模型是"一个工作台，多个任务"，不是"多个应用"。
